ANNOTATIONS:

@Component (class level): Spring by default won't create the object of all the classes in the IOC Server. we have to explicity tell spring in someway to create the
             object of these specific classes and we do that by giving the @Component annotation, and those classes are called Bean Classes.

@Autowired (field or method level): Using one java class inside another java class.

@Primary (class level): the use of this annotation is, when there is multiple classes implementing the same interface, then give preference to the class with this
           annotation.

@Qualifier (field or method level): when we don't want to use @Primary, we use this @Qualifier at the time of dependency injection by giving the instance name.
                - Class name is "Laptop" --> instance name is "laptop" (first letter small letter)
                - So in case of confusion it will pickup the mentioned class.

@Controller (class level): Marks a class that handles web requests, such as requests mapped with @GetMapping or @PostMapping.
              By default, if a method returns a String, Spring treats it as the name of a page to show.
              To send data directly back to the user, use @ResponseBody on the method or use @RestController on the class.

@Service (Class level): we use this for a Service Layer classes, in the background this is similar to @Component only.

@ResponseBody (class or method level): Tells Spring to send the method's returned value directly in the web response, instead of looking for a page.
              If the method returns an object, Spring can convert it to JSON. When added to a class, it applies to all request methods in that class.
                - com/bhargavspring/demoApp/controller/HomeController.java

@RestController (class level): Used for classes that handle web requests and send data directly back in the response, often as JSON.
              It combines @Controller and @ResponseBody, so you do not need to add @ResponseBody to every method. It is commonly used for REST APIs.
                - com/bhargavspring/demoApp/controller/HomeRestController.java

@PathVariable (method parameter): Gets a value from a variable part of the URL and passes it to the controller method.
              For example, in "/products/{id}", the value in place of {id} is passed to the id parameter:
              @GetMapping("/products/{id}")
              public Product getProduct(@PathVariable int id) { ... }
              If the variable name and parameter name are different, write the URL variable name in @PathVariable, for example @PathVariable("id") int productId.

@RequestMapping : - It is a general-purpose annotation that supports different HTTP methods, such as GET, POST, PUT, DELETE and PATCH.
                  - used to map incoming HTTP requests to a specific controller class or handler method based on the URL path, HTTP method,
                    request parameters, headers and other request conditions.
                    - eg :     @RequestMapping(value = "/students", method = RequestMethod.GET)
                               public String getStudents() {
                                   return "Student Details";
                               }
                    - Supports all HTTP methods.
                    - Class and method level

General annotation	                                Shortcut annotation
@RequestMapping(method = RequestMethod.GET)	    -   @GetMapping
@RequestMapping(method = RequestMethod.POST)	-   @PostMapping
@RequestMapping(method = RequestMethod.PUT)	    -   @PutMapping
@RequestMapping(method = RequestMethod.DELETE)	-   @DeleteMapping
@RequestMapping(method = RequestMethod.PATCH)	-   @PatchMapping

@RequestBody (method parameter): Tells Spring to read data from the HTTP request body and put it into the method parameter.
              For example, a client can send a JSON product in a POST request, and Spring converts that JSON into a Product object.
              Use it when the request sends data in its body; it is commonly used with @PostMapping or @PutMapping.

@Repository (class level): Marks a class that reads from or writes to a database. It is part of the data access layer.
              Spring creates and manages the class as a bean. Spring Data repository interfaces are usually detected automatically,
              so you do not need to add @Repository to them yourself.

@Entity (class level): Marks a Java class as data that JPA should store in a database table. Each object of the class represents one row in that table.
              Example: an object of a Product entity can represent one product row in the database.

@Id (field level): Marks the field that uniquely identifies each saved object (row) in the database table. This field is the table's primary key.
              Each entity must have an @Id field. For example, a productId field can be the ID for a Product entity.

*) Dependency Injection (DI) : In Spring Boot, Dependency Injection (DI) means one class gets the object it needs from Spring,
   instead of creating that object using new.
- Actual Implementation of IOC

- Three techniques to achieve dependency injection

1. Constructor Injection (Recommended)
The service object is injected through the constructor of the controller.

@Service
public class MyService {

    public String getMessage() {
        return "Hello from Service";
    }
}

@RestController
public class MyController {

    private final MyService myService;

    // Constructor Injection
    public MyController(MyService myService) {
        this.myService = myService;
    }

    @GetMapping("/hello")
    public String hello() {
        return myService.getMessage();
    }
}

How it works:
1. Spring creates the MyService object.
2. Spring passes that object into the MyController constructor.
3. The controller uses the service.
Note: @Autowired is optional when there's only one constructor.



2. Setter Injection
The service object is injected through a setter method. The MyService class remains exactly the same.

@RestController
public class MyController {

    private MyService myService;

    // Setter Injection
    @Autowired
    public void setMyService(MyService myService) {
        this.myService = myService;
    }

    @GetMapping("/hello")
    public String hello() {
        return myService.getMessage();
    }
}

How it works:
1. Spring creates the controller object.
2. Spring calls the setMyService() method.
3. Spring passes the service object through that method.



3. Field Injection (NOT MUCH RECOMMENDED)
The service object is injected directly into the variable using @Autowired.

@RestController
public class MyController {

    // Field Injection
    @Autowired
    private MyService myService;

    @GetMapping("/hello")
    public String hello() {
        return myService.getMessage();
    }
}

How it works:
1. Spring creates the controller object.
2. Spring automatically injects MyService into the field.
3. No constructor or setter is required.

**) IMPORTANT LAYERS

- Inside a typical Spring Boot application, three common layers are Controller, Service, and Repository.

1. Controller (Presentation / Web Layer) (@Controller )
- Receives HTTP requests from clients and maps them to Java methods using annotations such as @RestController, @GetMapping, and @PostMapping.
- Reads request data, calls the appropriate service method, and returns a response (often JSON).
- Keep controllers focused on HTTP concerns; put business rules in the service layer.

- Important annotations : @Controller or @RestController or @ResponseBody, @RequestMapping or @GetMapping, @PostMapping, @PathVariable, @RequestBody

--------------------
2. Service (Business Logic Layer)
- When a controller wants the data it wont as the DB it ask the SERVICE LAYER.
- Holds application rules and coordinates work needed to fulfill a request.
- Is commonly marked with @Service so Spring can create and manage it as a bean.
- Is called by a controller and can use one or more repositories to read or update data.
- Example flow: Controller -> Service -> Repository.

- Important Annotations : @Service

--------------------
3. Repository (Data Access / Persistence Layer)
- Handles communication with the database, such as saving, finding, updating, and deleting records.
- In Spring Data, an interface can extend JpaRepository<Entity, IdType>; Spring provides its implementation at runtime.
- Is commonly marked with @Repository when writing a custom data-access class. Spring Data repository interfaces are detected automatically.
- Keep database access here rather than putting SQL or persistence code in controllers.

Note: These are application layers, not three mandatory Spring Boot services or separate network services. A small
      application may not need every layer, but separating their responsibilities makes code easier to maintain and test.
