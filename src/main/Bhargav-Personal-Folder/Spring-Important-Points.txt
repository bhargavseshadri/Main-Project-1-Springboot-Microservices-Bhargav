*) Dependency Injection (DI) : In Spring Boot, Dependency Injection (DI) means one class gets the object it needs from Spring,
   instead of creating that object using new.
- Actual Implementation of IOC

- Three techniques to achieve dependency injection

1. Constructor Injection (Recommended)
The service object is injected through the constructor of the controller.

@Service
public class MyService {

    public String getMessage() {
        return "Hello from Service";
    }
}

@RestController
public class MyController {

    private final MyService myService;

    // Constructor Injection
    public MyController(MyService myService) {
        this.myService = myService;
    }

    @GetMapping("/hello")
    public String hello() {
        return myService.getMessage();
    }
}

How it works:
1. Spring creates the MyService object.
2. Spring passes that object into the MyController constructor.
3. The controller uses the service.
Note: @Autowired is optional when there's only one constructor.



2. Setter Injection
The service object is injected through a setter method. The MyService class remains exactly the same.

@RestController
public class MyController {

    private MyService myService;

    // Setter Injection
    @Autowired
    public void setMyService(MyService myService) {
        this.myService = myService;
    }

    @GetMapping("/hello")
    public String hello() {
        return myService.getMessage();
    }
}

How it works:
1. Spring creates the controller object.
2. Spring calls the setMyService() method.
3. Spring passes the service object through that method.



3. Field Injection (NOT MUCH RECOMMENDED)
The service object is injected directly into the variable using @Autowired.

@RestController
public class MyController {

    // Field Injection
    @Autowired
    private MyService myService;

    @GetMapping("/hello")
    public String hello() {
        return myService.getMessage();
    }
}

How it works:
1. Spring creates the controller object.
2. Spring automatically injects MyService into the field.
3. No constructor or setter is required.

* We use a interface and a class as preferred, but what if we have more than one class implementing the same interface?
- @Primary : the use of this annotation is, when there is a confusion, then give preference to this class.
- @Qualifier : when we don't want to use @Primary, we use this @Qualifier at the time of dependency injection by giving the instance name.
                - Class name is "Laptop" --> instance name is "laptop" (first letter small letter)
                - So in case of confusion it will pickup the mentioned class.
